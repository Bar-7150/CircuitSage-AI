## 1. Project Overview

**CircuitSage AI** is an intelligent electronics troubleshooting assistant designed to help students, hobbyists, makers, and junior engineers systematically diagnose malfunctioning breadboard circuits, microcontroller projects, and sensor integrations.

The application pairs local open-weight language and reasoning capabilities (**Google Gemma 4**, running via a dedicated local runtime) with a **deterministic engineering rules engine**, an embedded **curated electronics knowledge base**, and persistent session tracking backed by **Express.js and Supabase Postgres**.

---

## 2. Problem Being Addressed

Debugging physical electronics is notoriously difficult for beginners:
* **Silent Failure Modes:** When code fails, software issues an error stack trace. When circuits fail, they fail silently: an LED remains unlit, an I2C display remains dark, or an ESP32 browns out without explanation.
* **Information Fragmentation:** Resolving a fault often requires searching across multiple 50-page datasheets, pinout charts, and forum threads.
* **Destructive Consequences:** Beginners frequently destroy microcontrollers by driving 3.3V logic pins with 5V sensor outputs or omitting current-limiting resistors.
* **Ungrounded AI Hallucinations:** Generic cloud chatbots (such as ChatGPT) hallucinate pinout numbers, make basic arithmetic errors, blur guesses with facts, and require continuous internet connectivity unavailable in shielded electronics labs.

---

## 3. Key Features

* **📷 Circuit Intake & Optional Photo Ingestion:** Submit observed symptoms, target board models, and connected pin configurations, with optional breadboard photo upload.
* **🧠 Local Gemma 4 AI Reasoning:** Generates ranked fault hypotheses, structural explanations, and targeted test questions without transmitting data to external cloud AI providers.
* **⚡ Deterministic Engineering Rules:** Mathematically verifies Ohm's law, LED forward currents, logic level compatibility ($5\text{V} \rightarrow 3.3\text{V}$ violations), and I2C pull-up termination.
* **🎯 Epistemic Classification (Three-State Honesty):**
  * 🟢 **Verified Fact:** Strictly backed by manufacturer datasheets, deterministic math, or user-measured readings.
  * 🟡 **AI Inference:** Probabilistic hypothesis generated by Gemma 4; requires empirical validation.
  * ⚪ **Unknown Assumption:** Missing electrical parameter; the engine refuses to invent default values.
* **🔍 Interactive Multimeter Probing Loop:** Recommends safe, step-by-step probe placement and measurement modes; user-entered readings dynamically eliminate false hypotheses.
* **📚 Curated Electronics Knowledge Base:** Sub-50ms local retrieval of verified component boundaries, pinouts, and common failure modes.
* **🔒 Cloud-Connected or Air-Gapped:** Supports Supabase Auth and cloud sync when connected, with a transparent fallback to local session storage when disconnected.

## 5. Technology Stack

| Layer | Technology | Primary Role |
| :--- | :--- | :--- |
| **Frontend** | Next.js (React / JavaScript / Tailwind CSS) | Responsive user interface, epistemic state rendering, and multimeter guidance. |
| **Backend** | Node.js, Express.js | Modular REST API (`/api/v1`), request validation, and diagnostic orchestration. |
| **Database & Auth** | Supabase Postgres, Supabase Auth, Supabase RLS | Relational persistence, user identity, and Row Level Security data boundaries. |
| **AI Inference** | Gemma 4 (Local Runtime: Ollama / llama.cpp / HTTP pipe) | Local open-weight reasoning, hypothesis synthesis, and clarifying questions. |
| **Knowledge Base** | Curated Electronics Knowledge Catalog | Structured pinouts, operating voltage limits, and common failure modes. |
| **Rules Engine** | Pure JavaScript Module | Deterministic computation of electrical formulas and logic level checks. |
| **Testing** | Jest, Supertest | Unit testing for rules engine and integration testing for REST API endpoints. |

## 8. Prerequisites

* **Node.js:** Version 18.17+ or 20.x LTS.
* **Package Manager:** `npm` (bundled with Node.js).
* **Local AI Runtime:** A compatible local inference provider (e.g., [Ollama](https://ollama.ai) or a local HTTP server) running Gemma 4.
* **Operating System:** Windows 10/11, macOS (Apple Silicon or Intel), or Linux (Ubuntu 22.04+).
* **Hardware:** 16 GB System RAM recommended. NVIDIA GPU (6 GB+ VRAM) or Apple Silicon recommended for accelerated inference; multi-core CPU supported.

## 10. Environment Variable Configuration

Create `.env` files in both the `backend/` and `frontend/` directories using the templates below.

### Backend Configuration (`backend/.env`)
```env
# Server
PORT=8000
NODE_ENV=development

# Supabase Persistence & Auth
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-supabase-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key

# Local Gemma 4 AI Runtime
GEMMA_RUNTIME_URL=http://127.0.0.1:11434
GEMMA_MODEL_NAME=gemma4:latest
INFERENCE_TIMEOUT_MS=30000

# Storage & Logging
LOCAL_STORAGE_PATH=./data
LOG_LEVEL=info
```

### Frontend Configuration (`frontend/.env.local`)
```env
# Public Supabase Client Config
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key

# Express API Base URL
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000/api/v1
```

> [!CAUTION]
> **Secret Hygiene:** Never commit `.env` files containing real API keys or passwords. Never expose `SUPABASE_SERVICE_ROLE_KEY` through any `NEXT_PUBLIC_` variable in the frontend bundle.

## 12. Supabase Project Setup

1. Create a new project in [Supabase](https://supabase.com) (or launch locally using the [Supabase CLI](https://supabase.com/docs/guides/cli)).
2. Navigate to the **SQL Editor** in the Supabase Dashboard.
3. Run the project schema migration located at `backend/migrations/001_initial_schema.sql` to initialize:
   * `profiles` (with RLS enabled)
   * `diagnostic_cases` (with RLS enabled: `auth.uid() = user_id`)
   * `case_messages`
   * `diagnostic_hypotheses`
   * `measurements`
   * `knowledge_sources`
   * `diagnostic_feedback`
4. In **Project Settings** $\rightarrow$ **API**, copy your `Project URL`, `anon public key`, and `service_role secret` into your backend `.env` file.

## 13. Local Gemma 4 Runtime Setup

CircuitSage AI communicates with a locally running Gemma 4 model over an isolated HTTP service adapter:

1. Install a compatible local runtime (e.g., [Ollama](https://ollama.ai) or a local `llama.cpp` server).
2. Pull or load the Gemma 4 open weights:
   ```bash
   ollama pull gemma4:latest
   # Or run via local server on port 11434
   ```
3. Test that the local runtime is listening:
   ```bash
   curl http://127.0.0.1:11434/api/version
   ```
4. Verify that `GEMMA_RUNTIME_URL` in `backend/.env` points to your local inference port.

> [!NOTE]
> **Multimodal Vision Stance:** If your local Gemma 4 runtime does not have multimodal vision enabled, CircuitSage AI automatically falls back to text-only symptom descriptions and pin selectors without errors.

## 15. Security Notes

* **Localhost Perimeter:** Express binds to `127.0.0.1` by default to prevent unauthorized network queries over shared Wi-Fi.
* **Token Verification:** All user mutations derive identity strictly from validated Supabase JWT access tokens.
* **Row Level Security (RLS):** Supabase database policies ensure users can never access or modify cases belonging to another user.
* **No Remote Code Execution:** CircuitSage AI does not compile or execute arbitrary code on the host machine.

## 16. Offline Limitations

> [!WARNING]
> **Explicit Network Dependency Boundary:** Cloud-hosted Supabase services (Auth, Postgres, Storage) **CANNOT** be reached without an active internet connection. Merely using Supabase does not make an app offline.

When disconnected from the internet:
* **What Works Offline:**
  * Local Gemma 4 AI inference (via `127.0.0.1`).
  * Deterministic engineering rules calculations.
  * Curated knowledge base retrieval (from local fallback store).
  * Interactive multimeter probing and hypothesis elimination.
  * Markdown diagnostic report export.
* **What Stops Working Offline:**
  * Supabase cloud user authentication (application operates in **Guest Mode**).
  * Cloud database syncing across multiple devices.
  * Remote Supabase image storage (images are cached locally in `./data/uploads`).

## 18. Known Limitations & Future Work

* **Initial Component Catalog:** The MVP supports 15 core components (ESP32, Arduino Uno, RP2040, basic LEDs, resistors, 2N2222 BJT, SSD1306 OLED, DHT11). Unsupported components are flagged as `UNKNOWN_COMPONENT`.
* **Hardware Dependence:** CPU-only inference may take 30–45 seconds per turn compared to 5–15 seconds on a CUDA GPU.
* **Future Work:** Automatic resistor color band camera detection, KiCad netlist import, and offline-to-online Supabase sync.
